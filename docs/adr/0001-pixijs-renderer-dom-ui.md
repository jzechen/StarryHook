# 渲染用 PixiJS,UI 用 DOM,不引入完整游戏框架

2026-11-26,项目动工时定下的技术路线:2D 渲染选 PixiJS(WebGL 渲染器 + 精灵/场景图/滤镜),菜单、图鉴等界面用 DOM 叠加;不引入 Phaser 这类完整游戏框架。

原因:本作是单场景、手感驱动的小游戏,绿条物理与鱼类行为曲线需要完全透明可控的数学;Phaser 的场景/补间/物理/输入全家桶在此收益小、抽象层重。PixiJS 只解决真正需要的渲染与精灵管理;中文文字交给 DOM 渲染更稳。原型与正式实现同栈,原型调好的手感参数直接迁移。

## Considered Options

- **原生 Canvas 2D**:零依赖、最透明,但精灵管理、滤镜、像素素材管线都要手写;放弃——用户明确要求使用现成渲染库。
- **Phaser**:场景/补间/输入/音频全家桶,护栏足,但对单场景小游戏过重,其物理/补间帮不上自定义手感,包体更大;放弃。
