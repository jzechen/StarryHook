# [PROTOTYPE · 抛弃式] 联机手感冒烟 · 双标签页最小回路(票 #66)

**永不并入 main。** 分支 `prototype/net-feel-smoke`,与 `prototype/touch-schemes`(#63)同款待遇。

## 回答什么

钉定 #64 的联机数字基线——下行 frame 20Hz / 上行 pos·input 30Hz / 远端插值缓冲 ~100ms——
是局域网推算值。本原型让用户双端实玩,裁决三件事并回填 spec 技术章节定稿数字:

1. **客人自己小游戏的输入手感**:0.45s 咬钩窗 vs 单向延迟(客端小游戏纯镜像,含蓄力条/浮标/锁移动,全部走网络);
2. **远端角色插值观感**:双快照线性插值(可调缓冲);
3. **行内 outcome 回执延迟**:卖鱼 intent → 房主执行 → event 回执(实测 RTT)。

## 怎么跑

```bash
pnpm dev
# 同一浏览器开两个并排窗口(后台标签页会被节流,读数失真):
#   http://localhost:5173/net-smoke.html?role=host
#   http://localhost:5173/net-smoke.html?role=guest
```

玩法:走到右侧「钓位」圈里,按住 E/空格/鼠标蓄力,松开抛竿;等待浮标 "!" 咬钩,
咬钩窗内按住进入小游戏(按住升条、松开沉条,罩住鱼直到右侧进度满)。
客人钓到鱼后点「卖鱼(行内回执)」按钮,看回执 RTT。

## 怎么裁决

右上「延迟预设」逐档加大(0 → 15 → 30(基线) → 60 → 100 → 150ms 单向),
每档实玩三件事,记录「开始难受」与「不可玩」的档位;插值缓冲滑条单独扫(观感②)。

## 架构忠实度(哪些是真的)

- **真 CoreLoop 三实例**:房主竿(本地)、客人竿(房主侧第二实例,网络位置覆盖
  `px/py/facing` 公开字段 + holding 电平输入)、客人本地移动积分器(交互源恒 null);
- **真物理/常数**:catchBar 绿条物理、TUNE 全套(咬钩窗 0.45–0.85s、移速 70px/s 等);
- **真消息目录形态**:`{v,type,seq,ts,payload}` 判别联合,frame/world/event/welcome/pos/input/intent 沿 #64;
- **真权威切分**:客人小游戏/经济全房主权威,客端零可变世界状态;客人位置本地权威、无回显;
- **真渲染件**:角色贴图 + characterMotion 行走/呼吸姿态、鱼/浮标贴图、小游戏面板几何沿 worldScene。

哪些是 stub:传输 = BroadcastChannel + 出方向可调人为延迟(单机必可靠有序,
比真 Wi-Fi WebRTC 乐观——读数是「下界」);世界 = 单屏一钓位;经济 = 计数器;
无信令/断线/存档/音频/触控。人为延迟是**均匀固定**的,真网络有抖动——
结论回填 spec 时应把「不可玩档位」向保守方向(更低)取整。
